# It's Your World

A personal hub ("world") where users add apps to one account. One Wasp codebase:
the **world shell** (`src/shell/`, `src/world/`) and **apps** (`src/apps/<id>/`).
Read `docs/apps.md` before changing code. If you're working on one app, also read
its handoff in `docs/handoff/` (e.g. `docs/handoff/portfolio-app.md`).

## Ownership

Different chats own different parts. Stay inside your area; for anything outside it,
write a note in `docs/handoff/requests.md` and ask Yasir.
- **World shell chat:** `src/shell/**`, `src/world/**`, `main.wasp.ts`, `.devcontainer/**`,
  `.github/**`, `scripts/diagnose.sh`, World models (`User`, `UserApp`).
- **Portfolio app chat:** `src/apps/portfolio/**`, Portfolio models + migrations,
  the portfolio parts of seed/tests/README. See `docs/handoff/portfolio-app.md`.
- **Arcade app chat:** `src/apps/arcade/**`, Arcade models + migrations,
  the arcade parts of seed/tests/README. See `docs/handoff/arcade-app.md`.
- App chats may add their one-line registry entries in `src/world/clientRegistry.tsx`,
  `src/world/serverHooks.ts` and `main.wasp.ts`. Apps never read another app's tables.

## Non-negotiable security rules (details in docs/apps.md)

Every app query/action: `"UserApp"` in entities, `await requireAppAdded(context, "<appId>")`
first, `userId` in every `where`, other users' records → 404. Add a smoke test for each.

## Workflow

- Work on a branch and open a PR to `main`; CI must be green. Don't push to `main` from an app chat.
- Verify with GitHub Actions (this cloud workspace can't download Prisma engines, so
  `wasp compile` doesn't run here). Read failures from check-run annotations via the API.
- Review screenshots on the `screenshots` (main) / `screenshots-<branch>` branches.
- Troubleshooting: don't ask Yasir to run commands one by one. Use or extend
  `scripts/diagnose.sh`, whose log is pushed to the `diagnostics` branch.

## Wasp

This project uses the Wasp framework.

### Docs

- Find docs via the index at https://wasp.sh/llms.txt
- Pick the docs map matching the Wasp version in `main.wasp.ts`.
- Prefer raw Markdown URLs from the docs map over guessing `wasp.sh/docs` URLs.
- If this file conflicts with versioned Wasp docs, trust the docs and tell the user this file may be stale.

### Wasp TypeScript Spec

- `main.wasp.ts` contains the Wasp version and the Wasp app specification.
- When it references app components/functions, import them from `src/` with `with { type: "ref" }`.
- `route(name, ...)` and `crud(name, ...)` take an explicit name.
- Other constructors take no name argument; the declaration's name is the imported identifier. For example, `job(sendReminder, { ... })` declares a job named `sendReminder`.
- `@wasp.sh/spec` is generated by Wasp, don't install it from npm.

### Fresh checkout

- Run `wasp install` before other Wasp commands in a fresh clone or worktree.
- Set up `.env.server` and `.env.client` from the example files or the project README.
- Run `wasp db migrate-dev`. Check the project README to see whether you also need to run a seed.

### Verification

- Run `wasp compile` to check if app is valid.
- Do not run `tsc` directly for validation.
